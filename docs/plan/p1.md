# P1 实施计划

范围：行情采集 → 股票关系 → 机会发现 → 策略生成与审批 → 历史回测与评估。P1 不含任何下单、持仓、风控执行。

任务编号 `P1-NN` 是执行与验收的最小单元，`S` 列对应父计划 `MKACG-691` 的子任务（S3–S8）。每个任务都必须能用「验收命令」在本机复现结论，命令不可执行即视为未完成。

## 1. 里程碑

| 里程碑 | 内容 | 任务 |
| --- | --- | --- |
| M0 | 设计基线（本文档集） | P1-00 |
| M1 | 数据可用：标的、K 线、真实行情、时段、质量 | P1-01 ~ P1-05 |
| M2 | 关系可解释：目标、相关性、快照、强弱、研究页 | P1-06 ~ P1-10 |
| M3 | 机会可发现：扫描、聚类、机会 API、驾驶舱 | P1-11 ~ P1-13 |
| M4 | 策略可审批：模板、状态机、策略页 | P1-14 ~ P1-16 |
| M5 | 回测可评估：引擎、成本、指标、报告 | P1-17 ~ P1-20 |
| M6 | 验收入口：一键冒烟与验收报告 | P1-21 |

关键路径：`P1-02 → P1-03 → P1-07 → P1-11 → P1-14 → P1-17 → P1-21`。任一环节延期，后续里程碑整体顺延，不允许跳过验收。

## 3. 与 S3–S8 的对应与偏差

| 父计划 | 对应任务 | 偏差与理由 |
| --- | --- | --- |
| S2 | 无（基础设施） | 本计划假设 S2 先完成骨架与 Compose。**偏差**：S2 列了 5 个服务，本设计需 6 个（新增 `scheduler`），见 `docs/architecture/overview.md` §5 |
| S3 | P1-01 ~ P1-05 | 保留全部验收项；补充「1m/5m/15m 滚动 90 天、1h 以上全量」的保留策略（存储量见 data-model §9）。历史深度受限于标的上市时间（AAPL 自 2026-03-04，约 248 根日线），不做放宽 |
| S4 | P1-06 ~ P1-10 | 一致；补充"显著变化"阈值可配置 |
| S5 | P1-11 ~ P1-13 | 一致；扫描耗时判据固定为 ≤5 分钟（227 标的实测可承载） |
| S6 | P1-14 ~ P1-16 | 一致；补充 `approved` 后内容只读的强约束（409），防止审批内容与回测内容漂移 |
| S7 | P1-17 ~ P1-20 | 一致；补充"无前视"的可执行判据（注入未来数据结果不变） |
| S8 | P1-21 | 一致 |

## 4. 实施约束

- 每个任务一个 PR，PR 描述列出该任务全部验收命令与实际输出摘要；不接受"代码写完但验收命令跑不通"。
- 新增依赖必须有理由（能用标准库或现有依赖就不加）；新增容器必须更新 `overview.md` 与 Compose。
- 任何影响决策的计算必须落在 `analysis/core`、`strategy/core`、`backtest/core` 的纯函数里，并由单测覆盖；service 层只做编排与 IO。
- 数据只能来自实测或录制的真实响应（fixtures），禁止手写"看起来合理"的行情。

## 5. 风险与依赖

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 真实美股源为未授权公开端点，可能限流或变更 | 关系分析降级 | 适配器可切换；降级到 OKX 指数口径并在 UI 标记来源；见 `docs/risk/external-dependencies.md` §5 决策 1 |
| 合约历史深度仅约 248 天 | 回测样本短、结论外推弱 | 用 1h/4h 提升样本内频次；报告中显式声明样本区间；见决策 3 |
| OKX 限流（40 req/2s，实测 429 真实发生） | 全量回补耗时长 | 分片 + 指数退避 + 缺口续采；回补是后台任务，不阻塞 API |
| 227 个 `instCategory=3` 混合美股/亚洲股/ETF/指数/私营公司 | 相关性口径混乱 | `asset_class` + `exchange` 分类；仅 `us_equity` 用真实行情；见决策 2 |
