本文是 v6 的功能清单和实现状态登记处，只回答一个问题：v6 需要的每项功能，前端和后端各自做到什么程度。阶段划分、依赖关系和阶段闸门记录在总控 issue MKACG-807，不在本文重复。

状态只有四种：

- `已实现`：代码、接口和测试都已在当前 `master` 上可用。前端必须有页面、组件或路由文件；后端必须有路由和测试文件，后端不适用的能力除外。
- `开发中`：对应 issue 已经派发并正在执行，代码尚未合入 `master`。
- `未实现`：当前 `master` 没有实现，后续由对应 issue 承接。
- `不适用`：该端明确不在本版本范围内，或者该能力只保留在后端、不通过 v6 页面暴露。

## 1. 产品定位与边界

`trading` 是个人自托管交易工作台。v6 的重点是市场分析、标的分析、持仓查看、策略研究和历史回测，自动化交易留到后续阶段。

本版本的边界：

- 不做真实下单、撤单、改单和平仓，不自动执行策略。
- OKX 账户和持仓只读；手动持仓只做本地记账，不向交易所发送任何订单。
- 策略只用于观察信号和回测，不修改真实账户。
- 行情、指标、信号、风险和回测必须由确定性代码计算；AI 只做已有数据的归纳，不决定交易。
- 页面和接口必须区分 live、delayed、stale、demo 和 backtest 数据，不把演示数据当成真实数据。
- 页面职责：首页回答「股市全局与全球信息」，一眼看到国债收益率与 VIX；关注列表只看已关注标的加全局风险读数，只放 VIX，不出现国债收益率与利差。

产品和领域规则以 `docs/prd/v2.md` 与《trading 产品功能与数据需求说明》v1.0 为准，本文不复制它们的正文。

### 2.2 只有后端实现

- 执行引擎：订单状态机、模拟成交、对账和重启恢复（`backend/app/execution/`）。
- 风控：规则判断、分级处置和风险事件读取（`backend/app/risk/`）。
- 策略审批状态机：草稿、验证、启用、暂停和实盘授权流转（`backend/app/strategy/approval.py`）。
- 组合虚拟持仓：资金分配、虚拟成交、敞口和调整申请（`backend/app/portfolio/`）。
- 交易流水聚合：策略、回测预期、执行快照和日志的读模型（`backend/app/journal/`）。

执行、风控、审批、组合和流水在 v6 不通过页面暴露，属于后续自动化阶段的基础能力，保留在后端。用户策略与版本接口已由 S4-2（MKACG-828，PR #81 已合并）接入策略页，转入 2.1。

## 4. 更新规则

- 完成一个 issue，就在同一个 PR 更新它负责的行，不允许等功能全部做完再补。

## 5. 数据管道

宏观数据是本项目第一条完整的取数管道；未来的新闻与行情渠道沿用同一套结构，不另起管线。

```
Provider（取数） → Scheduler（进程内定时） → Middleware Pipeline（enrich / upsert） → 落库 + 事件总线
```

- **Provider**：实现 `app/core/ports/observations.py` 的 `ObservationProvider`（`name` / `supports(series)` / `fetch(series, since)`）。上游地址只从 `app/config.py`（环境变量）读取，实现里不写 URL。宏观现有 `treasury` / `cboe` / `yahoo` 三个实现，用哪个由 `settings.data_sources.macro.series` 决定，改配置即换实现。
- **Scheduler**：`app/jobs/market_data.py`，一个 tick 周期拉一次；同一「序列 + 粒度」同时只跑一次，重叠触发跳过并记日志；失败按 1×/2×/4× 周期退避，连续 3 次标记 degraded（`degraded` 只用于健康展示，退避窗口结束后仍放行一次试探抓取）。`app/macro` 内部没有任何定时原语。
- **Middleware Pipeline**：`app/macro/pipeline.py`，与通知域同一套洋葱模型（`mw(item, call_next)`，不调用即中止，异常不向调用方传播），但是独立实例、独立注册表。`enrich` 按 `ts` 算出归属交易日与交易时段，`upsert` 按唯一键写库。
- **落库**：`macro_observations` 以 `(series_id, ts, provider)` 为唯一键幂等 upsert；序列名称与单位来自代码里的序列清单，来源地址由当前 provider 配置决定，不另存定义表。管道返回「是否走完整条链 + 实际写入行数」，落库失败会记为 failed，不会被吞成成功。
- **事件**：宏观数据本轮不接通知。需要时在管道末端产出事件，交给通知域现有的 `Sink` 接口投递，不改本管道的落库层。

新增一个数据源 = 新增一个 `ObservationProvider` 实现 + 在调度配置里加一行；不改管道、不改落库层、不改通知。

阅读与抓取分离：`GET /api/macro/overview` 只读库，永不触发上游请求；抓取只由调度器与手动 `POST /api/macro/sync` 发起。
