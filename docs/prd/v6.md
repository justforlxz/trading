本文是 v6 的功能清单和实现状态登记处，只回答一个问题：v6 需要的每项功能，前端和后端各自做到什么程度。阶段划分、依赖关系和阶段闸门记录在总控 issue MKACG-807，不在本文重复。

状态只有四种：

- `已实现`：代码、接口和测试都已在当前 `master` 上可用。前端必须有页面、组件或路由文件；后端必须有路由和测试文件，后端不适用的能力除外。
- `开发中`：对应 issue 已经派发并正在执行，代码尚未合入 `master`。
- `未实现`：当前 `master` 没有实现，后续由对应 issue 承接。
- `不适用`：该端明确不在本版本范围内，或者该能力只保留在后端、不通过 v6 页面暴露。

## 1. 产品定位与边界

`trading` 是个人自托管交易工作台。v6 的重点是市场分析、标的分析、持仓查看、策略研究和历史回测，自动化交易留到后续阶段。

本版本的边界：

- 不做真实下单、撤单、改单和平仓，不自动执行策略。
- OKX 账户和持仓只读；手动持仓只做本地记账，不向交易所发送任何订单。
- 策略只用于观察信号和回测，不修改真实账户。
- 行情、指标、信号、风险和回测必须由确定性代码计算；AI 只做已有数据的归纳，不决定交易。
- 页面和接口必须区分 live、delayed、stale、demo 和 backtest 数据，不把演示数据当成真实数据。

产品和领域规则以 `docs/prd/v2.md` 与《trading 产品功能与数据需求说明》v1.0 为准，本文不复制它们的正文。

## 2. 当前实现总览

本节按 `master` 的实际情况分组。只在单端完成的能力放在对应分组；两端都尚未合入的功能统一放进“两端都未实现”并标注 `开发中`，避免把未合并的代码算作已交付。

### 2.1 前端和后端都已实现

- 自选搜索、加入、移出和分组（`frontend/src/pages/watchlist/index.tsx`）。
- 自选页 v6：分类筛选、真实指标列（趋势、RSI(14)、ATR(14)%、K 线覆盖）（`frontend/src/pages/watchlist/index.tsx`、`backend/app/watchlist/metrics.py`）。
- 标的详情的基础信息、K 线窗口、MA、RSI、MACD、ATR 指标卡（`frontend/src/pages/instrument-detail.tsx`）。
- 回测历史、排名、汇总指标和逐笔交易列表的只读查看（`frontend/src/pages/backtests/`）；发起入口等 B7 改为策略版本口径。
- 设置页现有基础配置、API Key 只写不读和密钥掩码（`frontend/src/pages/settings/index.tsx`）。

### 2.2 只有后端实现

- 执行引擎：订单状态机、模拟成交、对账和重启恢复（`backend/app/execution/`）。
- 风控：规则判断、分级处置和风险事件读取（`backend/app/risk/`）。
- 策略审批状态机：草稿、验证、启用、暂停和实盘授权流转（`backend/app/strategy/approval.py`）。
- 组合虚拟持仓：资金分配、虚拟成交、敞口和调整申请（`backend/app/portfolio/`）。
- 交易流水聚合：策略、回测预期、执行快照和日志的读模型（`backend/app/journal/`）。
- 首页聚合接口：市场、账户、风险、持仓、自选、提醒、策略与活动的八模块读取，每个模块独立降级（`backend/app/dashboard/`、`backend/app/api/routes/dashboard.py`）。
- 用户策略、不可变版本、规则 JSON、版本标的与回测关联：MKACG-816 的 `GET`/`POST /api/strategies`、版本、标的替换与标的详情关联接口（`backend/app/strategy/management.py`、`backend/app/api/routes/strategy.py`、`backend/tests/api/test_strategy.py`）。

执行、风控、审批、组合和流水在 v6 不通过页面暴露，属于后续自动化阶段的基础能力，保留在后端。用户策略与版本接口是 v6 策略页的数据来源，页面由 S4-2 交付。

OKX 只读账户与持仓、手动持仓流水：MKACG-812 的账户汇总、交易所持仓和手动持仓接口已合入；名义价值、合并持仓视图和持仓市值汇总仍未完成，功能总表按 `开发中` 登记（`backend/app/api/routes/positions.py`、`backend/tests/positions/test_api.py`）。

功能总表中还有以下后端接口已实现、前端尚未完成的行，不计入上述保留能力：K 线图、年化收益展示、策略列表、策略参数与版本、标的关联、新建策略草稿、`/api/strategies` 系列接口。

## 4. 更新规则

- 完成一个 issue，就在同一个 PR 更新它负责的行，不允许等功能全部做完再补。
- 只有代码、接口和测试都已合并，才能写 `已实现`。
- 删除旧实现时，把对应行移入 3.4，并写明删除归属 issue。
- PRD 与代码冲突时以代码为准，并在当次 PR 修正 PRD。
- 新增页面区块或 API 时，先补功能总表，再实现。
- `开发中` 只用于已经派发并正在执行的 issue；未派发的能力写 `未实现`，不提前写成 `开发中`。
