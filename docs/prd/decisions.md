本文件记录由 lxz 拍板、已经生效的产品与资金安全决策，以及这些决策对 [`v2.md`](./v2.md) 原文的改写。v3 相对 v2 的差异来源见 [`v3-delta.md`](./v3-delta.md)。

- 生效范围：本文件与 `v2.md` 冲突时，以本文件为准；`v2.md` 中已被推翻的原文已同步改写，不再保留旧口径。
- 决策来源：2026-11-10 在 MKACG-707 讨论中的拍板（Q1/Q3/Q4/Q5、D1/D2/D3），由总控 MKACG-691 汇总；本文件只做事实记录，不新增决策。
- 技术栈口径：PostgreSQL、单进程模块化单体、Podman 本地运行。这是项目约束，不是产品决策，记录在此只为消除歧义；具体工程约定见仓库根 `AGENTS.md`。
- 变更方式：新增或修改决策必须由用户明确拍板，并在本文件追加记录、同步改写 `v2.md`；工程实现不得自行扩大或收窄决策边界。

## Q1 删除 MCP

**决策**：v1 已交付的 MCP server 整体删除，不迁移、不保留接口，第一版不提供任何 MCP 能力。

**依据**：v2 全文没有 MCP 需求；PRD §三.10 的 AI 助手属后续扩展。v1 的 MCP 工具面全部围绕永续、机会扫描与审批状态机，在 v2 下无一可用。

**实施约束**：

- 删除 `backend/app/mcp/**`、`pyproject.toml` 中的脚本入口、相关数据表与文档、前端引用。
- 不保留兼容层、开关或旧接口 shim；删除即删除，git 历史保留。
- 门禁：`rg -i --pcre2 "(?<![A-Za-z0-9])mcp(?![A-Za-z0-9])" backend/app backend/pyproject.toml` 输出为空。

## Q3 SPOT + SWAP 双形态，同一产品页面一键切换

**决策**：第一版同时支持 OKX 现货（SPOT）与永续（SWAP）。二者是同一产品的两种交易形态（例如 `XAAPL-USDT` 与 `AAPL-USDT-SWAP`），在页面上可一键切换，切换时 K 线周期与指标参数保持不变。

**依据**：第一版标的范围是 `SPOT` 与 `SWAP` 两类并存，不是单一形态；现货与永续成对覆盖同一批代币化美股，永续另外提供做空与杠杆能力。

**实施约束**：

- `Instrument` 增加 `inst_type`（SPOT|SWAP）、`product_key`，以及仅 SWAP 非空的 `ct_val` / `ct_mult` / `ct_type` / `max_lever` / `settle_ccy`。
- 配对只在 `instCategory == 3` 内成立：现货 `product_key = baseCcy[1:]`，永续 `product_key = ctValCcy`；不得用「去掉 X 前缀」的字符串规则替代品类判断（加密资产中同样存在 X 开头的 base）。
- 标的详情接口返回同 `product_key` 的全部形态（`siblings`），页面提供 SPOT / PERP 切换，并同时展示另一形态的最新价与价差，不得暗示两者等价。
- `strategy/`、`indicators/` 内禁止出现任何 `inst_type` 分支；类别差异只允许出现在 `instrument/`（按类别规则集合的唯一真源）、`exchange/`、`execution/`，由 `backend/tests/architecture/test_no_inst_type_branch.py` 把关。
- 门禁：`ls backend/app` 与 `backend/tests/architecture/test_import_graph.py` 的 `PACKAGES` 对齐——当前是 15 个业务包，加上 `__init__.py`、`main.py`、`config.py` 三个文件；配对与形态用例由 `backend/tests/` 对应模块覆盖。

## Q4 实盘切换二次确认

**决策**：从模拟切换到实盘不设硬性资格门禁，但必须二次确认并留痕。

**实施约束**：

- 切换实盘的请求必须携带显式风险确认标记（`acknowledge_risk=true`），前端弹出二次确认。
- 确认动作写入交易日志（journal），可追溯操作时间与来源。
- 不实现按交易天数或成交笔数的实盘资格表；不拦截，只提醒与记录。
- 代理数据的回测结果不计入提醒中展示的模拟统计（见 D3）。

## Q5 允许真实美股代理数据源，独立分表

**决策**：允许使用真实美股行情作为代币化美股的代理回测数据源，用于补足代币化美股上市时间短（约 4 个月）的历史窗口。

**实施约束**：

- 代理数据源必须与 OKX 行情实现同一个历史 K 线端口，只提供真实存在的周期（真实美股无 24 小时连续行情，禁止合成 15m/1H 等周期）。
- K 线主键包含数据来源，并带 `is_proxy` 标记；代理数据与 OKX 行情分表存放。
- 一次回测只允许单一数据源，禁止跨源拼接。
- 代理数据是真实行情，不是模拟数据；PRD §八.8「不允许使用模拟数据冒充真实行情」继续有效。
- 回测结果与接口必须落 `data_source` 字段，界面以徽标标注「代理数据，与实盘标的不可比」。

## D1 SWAP 用于做空与杠杆：`max_leverage` 默认 3、硬上限 10、按档 clamp

**决策**：永续的价值是做空与杠杆。本地杠杆 `max_leverage` 默认 3、硬上限 10；单标的可用杠杆取 `min(max_leverage, instrument.maxLever)`，并按交易所 `position-tiers` 档位 clamp。

**依据**：v2.1 曾提出「本地杠杆锁死 1」，被 lxz 否定——永续不是为了只拿做空。实测代币化美股永续的 `lever` 最小值为 5，故默认 3 对全部标的成立，不需要逐标的例外表。

**实施约束**：

- 杠杆上限与强平是 SWAP 的一等参数：保证金模式固定逐仓（isolated），持仓模式固定净持仓（net）；账户实际模式与期望不一致时拒绝交易并提示，不得自动切换账户设置。
- 保证金与强平价按 `position-tiers` 档位查表，禁止用 `1/lever` 近似；档位查询用 `instFamily` / `uly`。
- 开仓前幂等同步 `set-leverage`；同步失败或返回杠杆不等于期望值时拒绝开仓。
- 强平价是纯函数（多空分别按维持保证金率计算），与交易所 `liqPx` 的一致性以对账为准，不宣称公式精确。
- 强平缓冲：预估强平价距现价不足阈值（默认 10%），或单笔初始保证金超过 `权益 × 1/max_leverage` 时拒绝开仓。
- 自动模式开仓必须同时挂交易所侧止损（algo 单）；止损提交失败则整笔开仓失败，禁止裸仓。
- `strategy/`、`indicators/` 禁止出现杠杆、保证金、强平分支。

## D2 资金费计入回测 PnL 且默认开启

**决策**：永续回测必须计入资金费，`funding_enabled` 默认 `true`；关闭需显式传参，且该值随回测结果落库。

**依据**：永续进入第一版范围后，资金费是持仓成本的一部分；不计入会让永续回测系统性偏乐观，与 PRD「回测必须计入交易成本」矛盾。

**实施约束**：

- 资金费表按 `(inst_id, funding_time)` 唯一，只对 SWAP 采集，SPOT 无此概念。
- 每个结算点（8 小时网格）按 `notional × realizedRate` 计入 PnL：正费率多头付出、空头收取。
- 优先使用 `realizedRate`，缺失回退 `fundingRate`；两者都缺失时标记 `funding_missing`，不得静默当 0。
- 必须区分「真实为 0」与「数据缺失」；报告输出资金费总额、资金费占 PnL 比例与资金费覆盖率，覆盖率不足时显式标注数值。

## D3 代理结果禁止与真实标的同榜排序

**决策**：代理数据（真实美股日线）的回测结果与 OKX 实盘标的的回测结果分开存放、分开展示，禁止混合排序或聚合。

**实施约束**：

- 回测记录 `data_source` 非空，取值限定为 `okx`、`okx_spot`、`okx_swap`、`us_equity_proxy` 之一。
- 排行接口签名必须显式接收数据源参数，无默认值，缺参返回错误；生成的查询必须带数据源过滤。
- 前端 Backtests 页拆成「真实（`okx` / `okx_spot` / `okx_swap`）/ 代理（`us_equity_proxy`）」两个独立列表，不提供「全部」视图，不存在跨数据源对比入口。
- 任何查询不得跨 `data_source` 排序或聚合。

## L1 资金安全四件套

**决策**：SWAP 实盘必须具备以下四项保护，缺一不可：

1. 默认杠杆 3x。
2. 硬上限 10x（按档位 clamp 后仍不得超过）。
3. 预估强平价距现价不足 10% 时拒绝开仓。
4. 自动模式强制交易所侧 algo 止损；止损提交失败则整笔不开仓。

**实施约束**：

- 四项均在 `execution/` 与 `risk/` 的强制路径上执行，不允许策略或配置绕过。
- 默认值与阈值经配置注入，但硬上限不得被配置抬高。
- 违反任一项时拒绝开仓并留下可追溯记录，不得降级为警告。

## D4 指标序列参数通道

**决策**：指标序列接口在冻结的路径与响应形状之外，增加一个**可选**查询参数 `params`（JSON 对象字符串，按指标名分组，形如 `{"rsi":{"period":14},"sma":{"period":20}}`）。不传时使用注册表默认参数；传了的部分逐项覆盖。响应中的 `IndicatorSeries.params` 回显本次实际生效的参数。

**依据**：详情页已支持多周期 K 线，T2.2 要求「调整参数后曲线随之变化」，而响应模型已冻结、不允许为参数再开第二个端点或加兼容路径。参数通道挂在同一条序列查询上，才能同时满足形状冻结与交互需求。

**实施约束**（2026-11-10 PL 决定，评审按此条复核）：

- 参数校验的唯一来源是 `IndicatorDefinition.params` 的 `ParamSpec`（`kind` / `minimum` / `maximum`）；接口层不平行维护第二份规则，交给 `app.indicators.compute`。
- 越界值、未知参数名、未知指标名、`params` 不是合法 JSON 或不是对象、未知周期、`limit` 越界，一律返回 422，不得裸 500。
- 参数只影响本次查询，不落库、不做组合模板持久化。
- `backend/contracts/openapi.json` 与 `frontend/src/api/types.ts` 由既有导出/同步脚本重新生成并随改动一并提交。
- 前端只透传用户输入的参数，不在前端解释参数语义或自行计算指标。

## D5 详情页展示方向：指标卡片 + 分时折线

**决策**：详情页不再画蜡烛图，改为「关键指标卡片 + 一条收盘价折线」。首批固定四张卡片：MA(20)、RSI(14)、MACD、ATR(14)；折线只连所选周期的收盘价，周期切换时折线与卡片一起刷新。

**依据**：2026-11-10 项目负责人明确更正方向，原话是「方向错了，我不需要一个新的 trading view，我只需要简单的卡片形式展示关键技术指标，以及分时折线图。后台执行策略可以使用 k 线，界面没必要。界面设计上不要过度了。」

**实施约束**（评审按此条复核）：

- 卡片数值只能取自 `GET /indicators/series` 的返回值，前端不重算指标；方向（比上一期上升或下降）只能通过比较相邻两个返回值得到。
- 折线只有收盘价一条线，不画蜡烛、影线、成交量、十字光标、缩放，也不叠加指标曲线。
- 不引入图表库，继续手写 SVG；几何计算放在 `frontend/src/lib/chart.ts` 的纯函数里，组件只负责渲染。
- 不新增全局状态库；页面在一屏内可见，不做专业交易终端的密集多面板。
- 后端两个接口与 `params` 参数通道保持不变（见 D4），本次只改界面。

## D6 交易时段按标的所属资产判，类别不承载时段语义

**决策**：交易时段由标的所属资产决定，不由类别决定。`SPOT` 与 `SWAP` 都既可能是加密资产，也可能是代币化股票，两类标的的交易时段完全不同：`BTC-USDT-SWAP` 与 `BTC-USDT` 全天候交易，`AAPL-USDT-SWAP` 与 `XAAPL-USDT` 按美股盘前 / 正常 / 盘后 / 休市。因此类别规则集合不承载时段语义，`TradingRules.session_kind` 仅作为资产类型缺失时的兜底默认值，不得作为判定依据。

**依据**：2026-11-10 PL 裁定。T1.11 已合并的实现里 `SPOT` 取 `crypto_24_7`、`SWAP` 取 `equity`，等于用类别代替了资产；而两类标的都会同时出现加密资产与代币化股票（`BTC-USDT-SWAP` 是加密永续，`XAAPL-USDT` 是代币化股票现货），按类别取时段必然有一半判错。时段是资产属性，不是类别属性。

**实施约束**：

- 时段判定的唯一入口按标的的 `asset_type` 取值：`crypto` 全天候（`24_7`），`tokenized_equity` 按美股盘前 / 正常 / 盘后 / 休市。
- `TradingRules.session_kind` 降为兜底默认值，只在资产类型缺失或未知时使用；任何模块不得以它作为时段判定的依据。
- 本条**只改文档定位，不要求改代码**：T1.11 已合并的 `TradingRules` 字段保持不动，代码侧由 T1.7（MKACG-746）按 `asset_type` 取值。
- 本条只有一种说法，落在 `v2.md` §二「交易类别与资产」与 §三.2「混合行情与交易时段」两处；两处都按本条写，不得出现第二种。
