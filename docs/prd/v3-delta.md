# PRD v3 差异说明

本页只记录 v3 相对 v2 的差异来源与影响面。PRD 正文见 [`v2.md`](./v2.md)，逐条决策见 [`decisions.md`](./decisions.md)；本页不重复抄写两者的内容。

## 差异从哪里来

- 规划来源：**MKACG-740**（v3 规划：既有节点逐条归类 + 新增节点正文，三轮核对通过）。节点判据与节点正文以该 issue 和总控任务图 MKACG-691 为准。
- 产品口径来源：项目描述。已确认的变化写在 MKACG-740 正文的「已确认的变化」一节：PostgreSQL 存储、`SPOT` 与 `SWAP` 两类标的并存且类别可扩展、混合行情体系、实盘默认关闭、持仓周期是策略参数、策略必须是确定性程序、界面从简。
- 落地影响：`v2.md` 按 v3 改写，`decisions.md` 逐条订正失效项，`AGENTS.md` 补三层分层与存储口径。承载节点是 MKACG-744，只改文档，不改代码。

## 既有节点怎么归类

MKACG-740 的 A 表给出每个既有节点的处置结论。定稿口径是三类：

| 结论 | 节点数 | 含义 |
| --- | --- | --- |
| 保持原样 | 11 | 与 v3 无冲突，其中 5 个带追加指令 |
| 改范围 | 21 | 结论不变，正文与验收按 v3 改写 |
| 废弃 | 0 | 没有节点被废弃 |

已合并的节点不回滚历史结论，只登记新的判据由谁承接。承接关系以 MKACG-740 的对应段落为准，例如 T0.3 → T0.7、T0.5 → T0.8、T1.1 → T1.9、T1.2 → T1.10、T1.3 → T1.11。

## 新增了哪些节点

新增 16 个：规划阶段 11 个，执行时补建的承接节点 5 个（标题带「承接」后缀）。逐个节点的 issue 号、阶段与前置依赖见 MKACG-691 的「新增的 16 个节点」表与 MKACG-740 的 C 节，本页不重复。

新增节点补齐的缺失能力（MKACG-740 的 B 表）：

- 股票动态相关性与关系矩阵。
- 关系网络。
- 市场共振与市场广度。
- 目标驱动与市场驱动的机会发现。
- 方向性策略与相对价值策略的组合生成。
- 策略审批状态机。
- 全局组合管理与策略级虚拟持仓核算。
- 分级风险处置。
- PostgreSQL 基座与版本化迁移。
- 按类别的交易规则集合。

## 落到本仓库的三条硬事实

这三条已经由 MKACG-743 改完，文档里凡是提到相关处都按它们写，不按 v2 的旧文本推断：

1. 存储已全部换成 PostgreSQL，表结构只经 Alembic 版本化迁移（`backend/alembic.ini`、`backend/migrations/`）。
2. 测试每个用例一个独立 PostgreSQL schema，跑测试前先 `make db-up`。
3. `backend/app/instrument/rules.py` 的 `TradingRules` 有 10 个字段，类别取值是 `SPOT` 与 `SWAP`；类别分支门禁只允许出现在 `instrument`、`exchange`、`execution` 三个目录。

## 阶段划分

v2 的 Phase 1–6 被 P0–P4 取代，阶段名依次是 P0 工程基座、P1 交易前准备、P2 风控管理、P3 交易执行、P4 AI 辅助。各阶段的内容、进入闸门、节点顺序与前置关系以 [`v2.md`](./v2.md) §七和 MKACG-691 为准，本页不再复述。
